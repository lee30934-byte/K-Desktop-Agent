# 휴대폰 아바타 · 명령 웹 화면

PC의 KDA가 켜져 있으면 휴대폰 브라우저에서 아바타, 음성·텍스트 명령, 최근 결과 및 현재 대화 작업 정지를 사용할 수 있다. 기존 세라믹 아바타와 관절 모션, 음성 변조 6종을 재사용한다.

## 연결

1. PC와 휴대폰을 같은 개인 Tailscale 네트워크에 연결한다.
2. 별도 승인 후 `scripts/mobile-private-access.ps1 -Apply`로 개인 HTTPS 8443 → PC 127.0.0.1:17677 연결을 구성한다. `-Apply`가 없으면 조회 및 계획만 출력한다. 기존 443 또는 8443 구성을 덮어쓰지 않는다. Funnel을 켜지 않는다.
3. 새 기능이 포함된 KDA에서 설정 → Telegram 섹션 → 휴대폰 아바타의 접속 주소에 `https://smm.tail073974.ts.net:8443`을 입력하고 연결을 켠다. PC 앱 재시작 시 서버는 다시 꺼진 상태다.
4. 휴대폰에서 같은 주소에 접속하고 PC의 일회용 연결 코드를 입력한다. 코드는 10분·1회 유효하다. URL·클립보드·로그·영구 파일에 코드를 자동 저장하지 않는다.
5. 명령할 대화를 선택한다. 그 대화의 PC 모델·프로젝트 설정과 기존 승인 조건을 그대로 따른다. 파일 첨부, 새 대화 생성, 휴대폰의 직접 엔진 설정 변경은 제공하지 않는다.

PC가 필요한 승인 요청은 결과 화면에 표시한다. 원격 승인 자동 허용은 추가하지 않는다. 정지는 현재 대화의 KDA 작업을 대상으로 하며 외부 분리 프로세스의 종료를 보장하지 않는다.

## 음성 및 브라우저 조건

마이크는 HTTPS의 보안 컨텍스트와 사용자가 누른 통화 버튼으로 시작한다. 마이크 사용 허용이 필요하다. 작업은 선택된 Claude/Codex 등의 모델, 음성은 기존 Codex 음성 엔진을 사용한다. 동시에 통화 하나만 허용하며, PC 또는 다른 휴대폰 통화가 있으면 새 통화는 실패를 표시한다.

음성 연결의 SDP·lease·command·오류는 인증된 세션별 이벤트로 전달한다. 이벤트 유실, 단절, 요청 시간 초과는 오류로 표시하고 음성 통화나 작업을 자동 재접수하지 않는다. 기존 통화 시간/연장·변조·마이크 해제 로직은 VoiceSession을 재사용한다. 실제 iOS/Android 마이크·출력·화면 잠금 후 동작·청감은 별도 기기 검증 대상이다. 브라우저를 닫을 때 통화를 종료하고, 휴대폰 연결이 90초 이상 끊기면 PC도 세션을 만료시키고 통화를 종료한다. 접수한 PC 작업은 계속된다.

## 권한과 수명

- HTTP 서버는 127.0.0.1만 수신한다. 방화벽·공개 URL·공유기 설정을 변경하지 않는다.
- 한 번 쓴 코드는 폐기한다. 기기별 인증 토큰은 해당 탭의 sessionStorage에만 저장하며 최대 8시간, 미접속 90초다. PC의 모든 연결 해제로 폐기된다.
- 연결한 기기는 KDA의 대화 이름과 선택한 대화의 최근 답변을 조회하고 그 대화에 명령할 수 있다. 코드는 개인 PC 작업 권한이므로 타인에게 전달하지 않는다.
- Host/Origin·JSON·요청 크기·메서드·음성 UUID/소유권을 검사한다. 실행 API는 인증 헤더와 동일 출처 POST가 필요하다. 임의 네이티브 명령 전달 기능은 없다.
- 명령 UUID를 접수 전에 기록해 같은 전송을 두 번 실행하지 않는다. 상태 조회는 실행 재접수 원장 한도를 소비하지 않는다. 실행 요청 256개 이후에는 새 연결이 필요하다.
- PC는 요청이 아직 유효한지 1회 claim 후 기존 공통 handler로 전달한다. PC가 접수하기 전에 연결을 해제하면 그 요청은 취소된다. 이미 접수한 작업은 연결 해제만으로 중단하지 않는다.
- 음성 이벤트는 소유한 기기에만 전달한다. 128개 버퍼를 넘겨 유실되면 통화 재연결을 요구한다.

## 구조와 빌드

`src/mobile/` → 독립 Vite 번들 `sidecar/dist/mobile/` → 기존 Tauri sidecar 리소스에 포함. PC 전체 앱을 휴대폰으로 내보내지 않는다. `npm run build`는 PC 및 휴대폰 화면을 모두 빌드한다.

`MobileHost`의 HTTP 요청 → stdout `mobile_request` → Rust 기존 이벤트 브리지 → `MobileDesktopBridge` → App의 `assistantHandlers` → 기존 전송·정지·대화 소유권·프로젝트·승인 게이트. 음성 제어는 기존 `voice_control`과 VoiceHost를 사용한다. API 키와 구독 자격 증명은 휴대폰으로 전달하지 않는다.

## 검증

`node sidecar/test-mobile.mjs`: 실제 loopback HTTP에서 인증·중복 실행·수명·claim·음성 소유권/유실 차단.

`node scripts/build-mobile-fixture.mjs` → `py -3 scripts/probe-mobile-companion.py`: 실제 PC 연결 컴포넌트와 실제 휴대폰 빌드를 함께 열어 pair → 대화 선택 → 전송 → 결과 → 전환 → 승인 표시 → 정지 → 모의 음성 SDP/오류 → 재접속 → 연결 해제를 검사. 업무 handler만 격리 대역이며 개인 DB·실제 모델·장치·앱 설정에 접근하지 않는다.

`evidence/mobile-companion-20261106/state.json`이 검증 상태, 해시, 로그 및 미검증 범위를 기록한다. 검증 완료는 설치·네트워크 허용·실제 휴대폰 통화 완료를 뜻하지 않는다.

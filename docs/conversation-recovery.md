## 동작

- 작업 현황에서 새 대화 생성, 기존 대화 추가, 대화 선택. 실행/예약이 없는 항목만 목록에서 닫기 가능. 목록 닫기는 대화 및 사용자 정지를 보존한다. 2026-10-31 후속 요청으로 작업 현황의 대화 삭제 버튼·연결·삭제 확인 경로를 제거했다.
- 마지막 대화와 패널 열림 상태 복원. 작업 목록·실행 상태·예약·첨부 바이트는 SQLite `conversation_workspace`에 순서대로 저장. 실패 시 화면 알림. 일시적인 blob 미리보기 URL은 저장하지 않는다.
- 모든 새 요청은 전송 전에 `long_tasks`에 원래 요청과 첨부를 기록한다. 재시작 시 최신 중단 실행과 일치하는 명시적 복구 기록만 자동 복구 후보로 사용한다. 오래된 모호한 행, 완료/실패 상태, 삭제된 대화, 사용자 정지/전체정지 상태는 자동 재실행하지 않는다.
- 자동 복구는 기존 설정을 따른다. 원래 요청·저장된 대화 이력·작업 상태를 읽고 완료 결과 및 분리된 작업을 먼저 확인하도록 전달한다. 모델의 실제 작업 중복 방지를 완전히 보장하지는 않는다. 원래 첨부는 보존된 바이트로 재첨부하며, 복원할 수 없으면 보류한다.
- 정지 요청 상태로 재시작한 행은 종료 확인 완료로 표시하지 않는다. 사용자 정지를 보존하고 자동 재개를 보류한다. 중단 실행이 있으면 그 실행 복구보다 예약이 먼저 실행되지 않게 한다.

## 정지 불응 시 사용

1. 정지/전체정지 요청 후 실제 종료 ACK를 기다린다. 30초 안에 확인되지 않거나 정지 전송이 실패하면 종료 잠금과 예약을 유지하고 복구 안내를 표시한다.
2. 작업 현황 또는 안내에서 **실행 엔진 복구** 선택. 다른 대화 실행도 모두 중단된다는 앱 확인창에서 확인한다. KDA 창은 유지한다.
3. Rust가 Node stdin과 독립적으로 KDA 관리 엔진의 프로세스 트리를 종료한다. `taskkill /T /F` 성공과 엔진 종료를 확인한 뒤 새 엔진을 시작한다. 시간 초과/실패 시 종료했다고 처리하지 않는다.
4. 대화와 일반 예약을 보존하고 추가 지시 대체 요청을 취소한다. 전체 자동 실행은 보류하며 필요할 때 사용자가 재개한다. 분리된 외부 작업의 종료는 보장하지 않는다.

원래 간헐적 불응의 단일 원인은 확정하지 않았다. 정지 IPC 대기 한도를 추가하고 무응답 엔진 복구 경로를 검증했다. OS 프로세스 종료 자체가 실패하거나 앱 UI 전체가 멈추면 기존 앱 재시작이 필요할 수 있다. 실행 중인 KDA를 대상으로 파괴적인 복구 버튼을 시험하지 않았다.
